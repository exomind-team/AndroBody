# AndroBody 路线图

**语言** · [简体中文](ROADMAP.md) · [English](ROADMAP.en.md)

**更新：** 2026-10-30。本文描述未来工作次序，不代表功能已经实现或验收。

## 不变的开发原则

AndroBody 必须持续把 Android 应用在理论上可能拥有的感知与行动能力纳入 Agent 可发现的能力地图。不能因为能力低频、实现复杂、尚未授权或当前设备暂时不支持，就从设计中删掉。

对每项能力分别表达：

1. **理论可能性**：Android API、设备硬件、组件、应用内执行环境或授权桥可能提供什么。
2. **当前可行性**：本机系统版本、设备、应用身份、已安装组件和用户授权允许什么。
3. **真实尝试与结果**：实际调用到了哪一步、系统或目标应用返回什么，以及独立观察证据。只有真实尝试碰壁后，才能把阻碍记为实测结论；静态分析只形成待验证假设。

每个结论要进入运行控制台，能追踪、导出、联调和作为回归样本。系统不允许、用户未授权、目标应用未提供合法入口、能力未实现和未测试必须分别呈现。未知不能被改写成失败或成功。

少数通用工具构成可扩展底座；专用工具、Agent 自制工具和 UI 在底座之上长出明确用途。专用描述不能凭空增加底层能力，也不能改变 Android 权限与用户策略。原生 Agent 的 Kotlin 底层实现要可复用、可追踪；后续可把通用能力特化为“启动应用”等易用工具。

## 当前基线

- Native 模式由 AndroBody 管理模型会话和工具循环；Gateway 模式由外部客户端发起请求、AndroBody 使用本机配置的模型并执行获准工具。直接 External Tool Service 尚未实现。
- 通知读取/发布、有限传感器读取、设备/电池/网络信息、TTS、受限本机录音、工作区文本文件 CRUD、会话管理与应用级运行控制台已有源码实现；各项系统权限、目标设备表现和端到端结果仍须分别验收。
- 上下文用量有只读检查；自动压缩、可核对的长期记忆、系统语音识别、通用 Intent、完整 Shell/PTY、Shizuku/Root 适配、Agent 可管理的一般触发器和直接 MCP/IPC 工具服务仍在路线中。
- 以 AndroidHarness 已体验的稳定版本为 Harness 与宽窄屏工作流主参照；Zafiro 补充流式会话和终端设计。只迁移已证实适合 AndroBody 权限、能力与证据合同的做法，不复制未实现功能或未发布的实验。

## 分阶段计划

### 1. 会话韧性与 Harness 基础操作

先消除“复杂任务稍久就断掉”及设备 UNKNOWN 后发送入口被锁死的问题。基于稳定会话身份支持排队、停止、恢复、分支、重命名、归档、删除和跨进程恢复；显示工具轮次、执行中项目、等待确认和部分结果。停止代表阻止后续工作，不抹去已发生的副作用。每次续跑先核对未决回执，不自动重放。

**验收重点：** 多次工具续轮、批量工具、长运行、取消、进程终止、UNKNOWN、网络恢复和跨模型切换都保留 session/request/trace 身份；失败后仍可继续对话、检查并恢复。

### 2. 开放世界能力目录与可行性检查

让 Agent 能按设备、API、应用身份和已授权桥查询能力。能力项包含理论接口或执行主体、必要权限、可行性未知项、真实调用记录、系统回执、独立观察和证据链接。目录允许逐步增加硬件、Android API、应用组件及合法授权桥，不把现有工具清单误作能力上限。

**验收重点：** 模型可区分“目录未覆盖”“代码未实现”“当前未授权”“当前环境不可行”“曾真实尝试且被阻断”“已执行但结果未知”和“独立观察已确认”。静态分析不得生成“当前无合法路径”的最终结论。

### 3. 通用 Intent 与通知动作

提供通用 Intent 构造和发送底座，覆盖 Android Intent 可表达的语义：action、data URI、MIME、category、显式组件与 package、flags、受类型约束的 extras、ClipData/URI 授权、selector、结果路由及可用的扩展字段。Activity、Broadcast、Service、前台 Service、Chooser、PendingIntent 等调用形态都要能被能力目录检查、表达或明确说明当前序列化/系统边界。不能只因少用就删掉理论入口。

系统后台启动限制、导出属性、签名权限、目标应用协议、组件不存在、用户确认等都是**可行性和回执状态**，不是从工具设计中抹去相关能力的理由。需要 Java 对象、Binder 或目标应用专属协议时，记录实际不可表示/不可调用的原因，并保留可扩展适配点。常用动作可复用同一 Kotlin dispatch、权限检查和收据链，特化成启动应用、开链接、分享、日历草稿等易用工具。

通知能力要同时覆盖读取和发布：身体页能看到真实收到的通知，Agent 可按权限读取；发布工具可组合标题、正文、样式、按钮和支持的点击动作。发布、系统展示、用户点击、目标应用完成业务分别给出不同回执。通知内容是不可信输入，模型外发仍按单独策略处理。

**验收重点：** Activity / Broadcast / Service 与各 Intent 字段类型有独立对照样本；包括未导出组件、缺失应用、权限拒绝、后台限制、Chooser、URI 授权、系统结果和取消。每个样本记录尝试阶段与设备实测，不把“系统接受派发”描述为业务完成。

### 4. Shell/PTY 与身体授权桥

建设受控 Shell/PTY，让 Agent 可使用 AndroBody 自身的应用进程/运行时能力；后续按同一授权和回执合同接入 Shizuku、Root 或其他合法桥。路径和身份不能因“是某 APP 的内部 Shell”而预先排除：先列入理论目录，再真实探查各自的 UID、可见文件、命令、环境、权限与限制。第三方非导出组件是否可调用也以真实尝试和证据判断。

控制面显示执行身份、工作目录、读写/网络范围、启动与停止状态、退出码、输出文件路径和撤权结果。危险操作可由人配置“用户审批、允许规则、拒绝规则”；授权范围只对明确的执行主体和资源生效。工具返回证据不等于副作用已回滚。

**验收重点：** 启停、并发、断连、超时、权限撤销、进程回收、文件隔离、网络边界、输出脱敏及恢复；主机、模拟器与实体设备分别留证。

### 5. 语音与本机音频产物

补齐输入/输出两端：系统 `SpeechRecognizer` 将语音转成可编辑文本再交给当前模型；录音可以开始、停止、播放、保存，并将受控的本地音频产物路径交给 Agent；TTS 对称播报回复。录音、识别、播报和未来 Omni 多模态传输是独立能力，权限和结果分别呈现。为 Omni 预留可传二进制音频的模型适配接口，不要求非 Omni 模型消费音频。

**验收重点：** 用户可随时取消并找回产物；路径可由 Agent 按授权读取；识别文本能修改；日志默认不含音频或转写正文；无可用引擎、拒绝麦克风、后台限制和文件读回失败均能定位。

### 6. 上下文压缩、归档与长期记忆

在只读用量检查之上实现可恢复的摘要检查点、按需原文回忆和连续任务压力恢复。摘要作为可检查的派生产物，不覆盖原会话；保留未决动作、工具回执、用户约束和来源范围。生成摘要的模型请求可能计费，自动策略需要用户明确设定模型、次数/费用边界和退出方式。

**验收重点：** 摘要提交中断、取消、存储满、Keystore 失败、跨模型和长工具历史；每次能恢复来源消息与会话身份，不丢失或重放设备副作用。

### 7. 事件触发与 Agent 维护工具

让人和 Agent 都能管理触发器：电量、通知、网络、传感器、时间和后续发现的 Android 事件。人类界面拥有高权限；Agent CRUD 只在用户已开放的事件源与工具范围内操作。触发器可指定条件、提示词、目标会话/Agent、工具集合、冷却、去抖、并发、有效期、失败和停止策略；动作仍经过同一工具调用协议、授权、运行控制台和回执链。

先做只读事件观察和“将会触发什么”预览，再逐步启用后台唤醒与获准动作。来源通知、广播、文件和模型输出只作为数据，不构成新授权。重复派发用幂等记录保护；每个执行可停止、可追踪、可导出。

**验收重点：** 重启与重复广播、OEM 后台限制、离线/省电、触发器版本变更、暂停/撤销竞态、权限撤销、动作 UNKNOWN 和有限重试。

### 8. External Tool Service 与生态集成

在 Native、Gateway 之上增加第三条模式：AndroBody 作为 MCP/IPC 工具服务供其他 Harness 调用。外部客户端拿到的是经用户授权的工具范围，不是 AndroBody UID、上游模型 Key、其他应用私有数据或 Android 权限继承。认证、可撤销令牌、客户端身份、逐工具授权、速率/并发、撤权和审计均须先于接入。

优先研究 AndroidHarness 与 Termux 等既有 Agent 生态实际可调用的协议；“外部模式”是通路，不替代专用工具或 Native/Gateway 会话。设计确认后，通用工具仍是底座，外部调用和专用工具共享实现与证据。

## 交互与验证约束

- AndroidHarness 的项目/聊天分工、模型选择、空状态示例、工具进度和恢复能力作为主参照；手机、平板和宽窄屏都要按实际视口验收。未发布的 Harness Glass 只作实验观察。
- UI 遵循 ARC 原则：少文字、按需披露、直接操作、真实状态；控制台承担深入诊断，聊天只显示当前任务需要的信息。动作、失败、等待审批、部分结果和未知状态要可见。
- 每个阶段用源码审查、主机、模拟器、实体设备和人工体验分别记录证据。计划、接口存在、权限开关和模型陈述都不能代替实际调用与独立观察。
- 能力增长同时保留拒绝与成功样本；无法复现的结果标为未知，并保留请求/trace/运行 ID、设备与版本范围，进入回归集。
